# M4 — Automated adversarial failure discovery and counterexample shrinking

Status: **implemented and measured locally; awaiting review.** A bounded, reproducible search
(Random Search or CMA-ES) looks for low-impulse trunk shoves that make the walking Go1 fall. Each
failure is confirmed by the authoritative paired runner, shrunk locally, and replayed against the
nominal robot in the M3 viewer.

Spec: `.kiro/specs/m4-failure-discovery/`. Branch `m4-failure-discovery`, from `main` after the
M3 merge (`8bb69f6`). That merge is of `m3-web-replay` at `e455db2`, i.e. tag `m3-baseline` =
`deeb350` plus the playback fix. One writer.

## Run it

```bash
uv sync --extra server            # includes pycma 4.6.0 (BSD-3-Clause)
uv run robustlab discover --algorithm cmaes --budget 64 --seed 0 --shrink-budget 32 --out runs/m4/x
uv run python scripts/compare_search.py --seeds 0-19 --budget 64 --shrink-budget 32
(cd web && npm ci && npm run build) && uv run robustlab serve    # Failure Discovery tab
```

## What is searched

| Parameter | Range | Resolution |
| --- | --- | --- |
| `force_n` | 10–150 N | 0.1 N |
| `direction_deg` | [0, 360), initial-heading horizontal plane, 0° forward, 90° left | 0.1° |
| start | [2.000, 3.024) s → substeps 500–755 | 4 ms |
| duration | 0.040–0.200 s → 10–50 substeps | 4 ms |

Fixed: command (1, 0, 0), 5 s horizon, `go1-walk-s0`, nominal reset, `fall-contact` scene. The
target is the **lowest impulse (force × duration) among confirmed physical failures found within
the budget**. The maximum impulse is 30 N·s.

**CMA-ES parameterization.** CMA-ES (pycma) works on `(fx/150, fy/150, u_start, u_duration)` in
`[-1, 1]² × [0, 1]²`. The force vector is projected radially onto the 10–150 N annulus, and
`(force_n, direction_deg)` are reported. Neighbouring directions are therefore neighbouring
internal points, with no 0°/360° seam. The time fractions map to substeps by floor. Other
settings:
- population 8, mean (0, 0, 0.5, 0.5), σ₀ = 0.4;
- pycma's default bound transform;
- a private NumPy generator through pycma's `randn` option, so NumPy's global random state is
  never used.

**Random Search** draws force uniformly in magnitude, direction uniformly, and start and duration
uniformly over their substeps. The two priors differ: random is uniform in force magnitude, while
CMA-ES starts Gaussian around zero force. Neither gets any prior failure information, and warm
starts are not implemented.

**Objective (minimized):**
- fell: `−2 + impulse/30`, in [−1.99, −1.0];
- survived: `min(tilt margin, height margin)` from the episode's minimum `up_z` and trunk height
  relative to 45° and 0.18 m, in [0, 1];
- numerical: `+2`, invalid, never a failure.

Hypothesis Property 24 checks the ordering: every fall < every survivor < every numerical result,
lower impulse first among falls.

**Three levels of failure, recorded separately:**
1. **Candidate:** one shoved rollout with a physical fall.
2. **Confirmed:** the lowest-impulse candidate re-simulated as a paired nominal + shoved trial
   through the M2 `run_trial`. Its shoved trajectory digest must match the candidate's, and the
   pre-shove trajectory must match nominal.
3. **Shrunk:** a lower-impulse failure found and confirmed by the shrinker.

**Shrinking** is a local coarse-to-fine pattern search, because the landscape is not monotonic:
1. Direction and start are held fixed. It tries force, then duration, at 50 / 70 / 85 / 95% of the
   current value.
2. A reduction is adopted only after it falls and confirms; that dimension then restarts at 50%.
3. Finally it "releases" timing and direction: at 95% force it tries starts ±1–2 substeps and
   directions ±5°.

Every tested point is recorded, along with the surviving points below the final impulse and an
explicit list of untested regions. The result is never claimed to be minimal.

**Accounting** (per run, every rollout counted): search rollouts (≤ budget), confirmation (2 per
attempt), shrink rollouts (≤ shrink budget), shrink confirmations (2 each) and 1 nominal reference.
A quantized candidate already evaluated is a cache hit, not a rollout; there were none in these
runs.

## Matched comparison: Random Search vs CMA-ES

Protocol: seeds 0–19 for both algorithms, budget 64 search rollouts, shrink budget 32, same code
and fixed experiment, no warm start. Recorded at `70a07c2` (clean tree), with summary in
`runs/m4/comparison/summary.json`, committed as `presets/discovery-comparison-v1/`.

| | Random Search | CMA-ES |
| --- | --- | --- |
| Runs that found a physical failure | **14 / 20** | **20 / 20** |
| Candidate falls per run (median) | 1 | 17 |
| Evaluations to first failure, median (runs that found one) | 11 | 12 |
| Confirmed search failure, median impulse | 16.14 N·s | 15.49 N·s |
| After shrinking, median impulse | 13.81 N·s | 11.07 N·s |
| Lowest found | **8.92 N·s** (seed 18) | 9.30 N·s (seed 3) |

**What the comparison supports.** With 64 rollouts on this problem, CMA-ES found a confirmed
failure more reliably: 20/20 against 14/20 (p = 0.020). That reliability is most of its advantage
on impulse.

**What it does not support.** When both found a failure, CMA-ES gave the lower impulse in 10 of 14
seeds, but p = 0.18 is not strong evidence. It was not faster to its first failure. The single
lowest failure came from Random Search (8.92 N·s). These are 20 seeds on one experiment
configuration, one budget and one prior per method. CMA-ES's prior concentrates on moderate forces,
which may by itself explain part of the difference. No claim is made beyond this setup.

**What the discovered failures look like:**
- **Stance:** 29 of the 34 final failures (Random 10/14, CMA-ES 19/20) start while the front-right
  and rear-left feet are in stance (FR+RL), the stance M2 identified for 100 N rightward shoves.
- **Direction:** 25 of 34 point to the robot's right, 242–300° (Random 9, CMA-ES 16), and 9 to its
  left, 88–133° (Random 5, CMA-ES 4).
- **Lowest found:** 139.3 N at 271.0° for 64 ms from 2.472 s (8.92 N·s), FR+RL stance, tilt fall at
  3.056 s, front-right hip first to the floor.
- **Shrinking:** lowered the confirmed impulse in 31 of 34 runs. The median reduction over all 34
  runs was 2.66 N·s (18%), and the largest 13.98 N·s (51%). It used a median of 26.5 rollouts and ran out of budget in 10 runs. Every
  adopted improvement was confirmed; no unconfirmed fall was ever adopted.

## Limitations

- **Budget-bounded result.** These are the lowest impulses found within 64 + 32 rollouts. Lower
  ones exist off the tested points; the 8.92 N·s found by one random seed beats every CMA-ES result.
- **Evidence for one setup only.** One configuration, one budget and 20 seeds. The impulse
  difference between methods is not significant where both found a failure. The two methods'
  priors differ, which affects the comparison.
- **Simplified disturbance.** A constant horizontal force at the trunk centre of mass with an
  instantaneous on/off: no torque, no contact, no vertical component, flat ground.
- **Narrow shrinking.** It explores one dimension at a time with four ratios, plus a small release
  step, so joint reductions and distant directions are not searched.
- **Server-side state.** One search at a time; the 120 s server limit is a setting, not a measured
  bound (observed runs took 6–8 s); job state is in memory, as in M3.
- **Not deployed.** As in M3, nothing is deployed and the server binds to 127.0.0.1.
- **Not pushed.** `main` was merged locally (`8bb69f6`) and is ahead of `origin/main` (`451fef8`).
  Pushing is left to you.
