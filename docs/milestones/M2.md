# M2 — Reproducible experiment runner (CPU)

Status: **implemented and measured; awaiting review.** One command runs a paired suite of nominal
and shoved episodes, varying only the shove start time, and writes a report with every trial's
timing, outcome, fall reason and time, and the paired difference.

Spec: `.kiro/specs/experiment-runner/`. Branch `m2-experiment-runner`, from `main` after the M1
merge (`4110edc`, merge of `m1-baseline` = `fee2cc9`). One writer; tree clean before every commit.
All runs below were recorded at `0b57e70`, clean tree.

## The command

```bash
uv run robustlab experiment --config examples/m2/sideways-shove-stratified-16.json \
    --out runs/m2/stratified-16
```

Also used:

```bash
uv run robustlab experiment --config examples/m2/sideways-shove-stratified-16.json \
    --out runs/m2/stratified-16-rerun --no-save-trajectories      # determinism check
uv run robustlab experiment --config examples/m2/sideways-shove-grid-all-256.json \
    --out runs/m2/grid-all-256                                     # every start substep
uv run robustlab experiment --config examples/m2/sideways-shove-stratified-16.json \
    --out /tmp/x --dry-run                                         # timings only
```

Outputs: `experiment.json` (machine-readable report), and for ≤ 32 trials
`trials/<NN>/{nominal,attacked}/{trajectory.json,manifest.json}` in the M1 format (schema 2), so M3
can replay any trial. The printed summaries are in `runs/m2/*.summary.txt`.

## What varies and what does not

The runner is deterministic: there is no sensor noise and no randomized reset, so rerunning one
episode with a different seed label reproduces it exactly. M2 varies one physical quantity, the shove
start time, which sets the gait phase at which the shove arrives. The measured nominal gait period
is 0.44 s per foot.

| | Value |
| --- | --- |
| **Varied** | shove start, on the 4 ms substep grid in [2.000, 3.024) s: 256 start substeps (500–755), 1.024 s ≈ 2.3 gait cycles |
| Fixed | 100 N toward −y (robot's right) in the initial-heading frame, 0.1 s (10 N·s), trunk COM; command (1, 0, 0); 5 s horizon; `fall-contact` scene (transform `e62fed8f…`); policy `go1-walk-s0` (`42138b2b…`); nominal reset state |
| Test distribution | shove start uniform over those 256 substeps, everything else fixed |
| Pairing | each trial = nominal run + shoved run, same reset, command, horizon, scene and policy, same `EpisodeRunner` |

Three kinds of evaluation, kept apart:

| Kind | Used for | How to read it |
| --- | --- | --- |
| **Randomized stratified sampling** (`stratified-16`) | 16 trials; trial *i* draws one start substep uniformly from its 16-substep stratum using `SeedSequence(20261121).generate_state(16, uint32)` | fall-rate *estimate* over the test distribution, with a sampling interval |
| **Exhaustive deterministic sweep** (`grid-all-256`) | every one of the 256 start substeps once | *exact failure frequency* over the test distribution in this deterministic model; no sampling uncertainty |
| **Repeated identical simulation** | the 16 (or 256) nominal runs, and the determinism rerun | one observation repeated; a reproducibility check, not evidence of a rate |

## Results

### 16-trial stratified sample (`runs/m2/stratified-16`)

Start substeps drawn: 502, 530, 532, 548, 577, 585, 599, 626, 632, 653, 671, 688, 697, 722, 727,
743 (one per stratum [500 + 16i, 516 + 16i)).

| Case | Physical falls / valid | Survived | Numerical failures | Distinct trajectories |
| --- | --- | --- | --- | --- |
| Nominal | 0/16 | 16 | 0 | **1** |
| Shoved | **0/16** | 16 | 0 | 16 |

- Fall-rate estimate 0/16 = 0.000; Wilson 95% interval **[0.000, 0.194]**. The interval treats the 16
  trials as independent draws; stratified sampling with equal strata has variance no larger than
  that.
- Paired table: 16 survived→survived. Mean forward progress: nominal 4.549 m, shoved 4.527 m
  (range 4.508–4.553 m); mean paired difference −0.022 m.
- Pre-attack parity: every Tick up to each shove start matched the nominal run exactly (max |diff|
  0 in qpos, qvel and action, all 16 trials).
- Determinism: `stratified-16` and `stratified-16-rerun` give the same start substeps, outcomes and
  `results_sha256 = e21e5897…1745e`. The integration test repeats this.
- Wall time: 4.15 s for 32 rollouts including trajectory writing; 2.08 s without.

### Exhaustive sweep, all 256 start times (`runs/m2/grid-all-256`)

| Case | Physical falls / valid | Survived | Numerical failures |
| --- | --- | --- | --- |
| Nominal (1 distinct trajectory) | 0/256 | 256 | 0 |
| Shoved | **11/256 = 4.3%** | 245 | 0 |

The 11 falling starts are 2.000, 2.020, 2.444, 2.448, 2.452, 2.808, 2.832, 2.884, 2.892, 2.896 and
2.900 s. Every one is a `tilt` fall 0.436–0.580 s after the shove starts (median 0.548 s). The first
non-foot contact is always the front-right hip. Fallen runs covered 2.10–3.01 m before falling,
against 4.36–4.57 m for runs that survived the shove. `results_sha256 = 66df5556…0a1cf`; 33.98 s for
512 rollouts.

| --- | --- |
| FR + RL (diagonal pair) | **11/110** |
| FL + RR (other diagonal) | 0/96 |
| FR only | 0/15 |
| FL only | 0/10 |
| no foot down | 0/25 |

### The two results compared

The exhaustive sweep gives each stratum's true failure fraction, so the distribution of the
16-trial stratified count can be computed exactly: P(0 falls) = 0.478, P(1) = 0.379, P(2) = 0.121,
P(3) = 0.020; expected count 0.69 (= 16 × 11/256). Drawing samples with the real sampler for seeds
0–1999 gave 0.483, 0.365, 0.134, 0.017. The observed 0/16 is the single most likely result, and the
Wilson interval [0, 0.194] contains the exact 0.043.

## What this establishes

1. **A measured failure frequency over a stated distribution.** In this simulation, this policy
   falls for 11 of the 256 start times of a 10 N·s rightward shove during [2.000, 3.024) s at 1 m/s.
   That is an exact count for this deterministic model on this build, not an estimate.
2. **Falls depend on gait phase.** All 11 falls happen while the front-right and rear-left feet are
   in stance. No fall happened in 146 shoves at any other stance pattern. The mechanism is
   consistent across falls: tilt past 45°, front-right hip first to the floor, about 0.5 s after the
   shove.
3. **M1's single demonstration was unrepresentative.** M1 shoved at exactly 2.000 s, one of the 11
   falling start times; 96% of start times in this interval survive the same shove.
4. **The pipeline is sound.** Pairing is exact before the shove; nominal runs are bit-identical;
   numerical failures are tracked separately (none occurred); reruns reproduce the report digest.
5. **16 trials cannot resolve a rate near 4%.** A 16-trial stratified run shows no falls almost half
   the time. The 16-trial result is honest (its interval reaches 19%), but it cannot distinguish
   "rarely falls" from "never falls".

## What this does not establish

- **Nothing outside the test distribution.** Other forces, directions, durations, commands, start
  intervals, terrains, payloads, friction or sensor noise were not tested. The left/right asymmetry
  seen in M1 is a reminder that direction matters.
- **No real-robot claim.** One simulator (C MuJoCo 3.15.0), an idealized trunk force, a policy
  trained in MJX Warp, a simplified collision model; no sim-to-real evidence.
- **Not a smooth threshold.** Outcomes change from one 4 ms start step to the next (2.884 s falls,
  2.888 s survives, 2.892 s falls). The frequency is a property of the 4 ms grid. Finer timing, or
  any small extra perturbation, could move individual outcomes; the 4.3% figure should not be quoted
  to more precision than that.
- **Falls after the 5 s horizon are not counted.** The latest shove ends at 3.120 s, leaving at
  least 1.88 s; every observed fall came within 0.58 s of the shove, but a later fall cannot be
  ruled out.
- **The nominal "0/16" is one observation.** The nominal runs are one deterministic trajectory
  repeated; they show the unshoved walk does not fall in 5 s, nothing more.
- **Not independent trials in the strict sense.** Stratified trials are random draws from disjoint
  strata, not i.i.d. samples. The Wilson interval is an approximation; for stratified sampling with
  equal strata its width is, if anything, conservative.
- **Identical results are claimed only within one build and machine.**

## Implementation

| Piece | File | Notes |
| --- | --- | --- |
| Shared loading and manifests | `experiments/stack.py` | `load_stack`, `Stack.manifest_for`; `walk` now uses it too |
| Config, sampling, pairing, aggregation, report, summary | `experiments/suite.py` | stdlib dataclasses with strict key and range checks; integer substep arithmetic |
| CLI | `cli.py` `experiment` | `--trials`, `--seed`, `--save-trajectories/--no-save-trajectories`, `--overwrite`, `--dry-run`; exit 2 invalid, 3 write, 4 pairing mismatch |
| Example configs | `examples/m2/*.json` | 16-trial stratified; 256-trial exhaustive grid |

Physics goes only through the M1 `EpisodeRunner`, `FallMonitor`, `PushScenario` and scene builder.
Each episode's outcome is exactly one of `survived`, `fell` (first event physical) or `numerical`
(first event numerical). `fall_rate = physical_falls / (total − numerical_failures)`, null when no
trial is valid. Stratified sampling requires the 256 start substeps to split into equal strata
(trials dividing 256), so the plain average is unbiased. `results_sha256` hashes the sampling
record, trials (without paths) and aggregates, not wall-clock times.
