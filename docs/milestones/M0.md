# M0 — Pretrained Go1 walking in native MuJoCo (CPU)

Status: **all M0 walking criteria passed.** Our independent NumPy + MuJoCo 3.15.0 runner drives
weeble's pretrained `go1-walk-s0` policy upright and forward on flat ground on an Apple M3 Pro CPU.
It reproduces weeble's reference runner exactly (max absolute error 0) over 500 closed-loop Ticks.

Spec: `.kiro/specs/m0-walking-go1/`. Scope: M0 only. No UI, scenario schema, LLM adapter, optimizer,
adapter, push perturbation or later-milestone stubs exist.

## What works

```bash
UV_PYTHON_DOWNLOADS=never uv sync --python /opt/homebrew/Caskroom/miniconda/base/bin/python3.12
uv run robustlab doctor
uv run robustlab verify-assets
uv run robustlab walk --policy policies/go1-walk-s0.json --command 1,0,0 --seconds 10 --out runs/m0/forward
uv run robustlab walk --policy policies/go1-walk-s0.json --command 0,0,0 --seconds 10 --out runs/m0/zero
uv run robustlab walk --policy policies/go1-walk-s0.json --command 1,0,0 --seconds 51 --out runs/m0/latency
uv run python scripts/render_final_pose.py
```

On this network every `uv` command was run with `UV_PYTHON_DOWNLOADS=never` and `--frozen`, because
uv's managed-Python download times out (see `docs/kiro_build_log.md`, Task 1). `walk` refuses to
replace an existing run unless `--overwrite` is passed; the recorded runs below used `--overwrite`.

## Control contract implemented

| Item | Value |
| --- | --- |
| Physics step / substeps / control period | 0.004 s / 5 / 0.02 s (50 Hz) |
| Actor | MLP 48 → 512 → 256 → 128 → 24, swish hidden, `tanh(logits[:12])` |
| Normalizer | `(obs − mean) / std`, float32, no epsilon, no clip (`obs_key = state`) |
| Observation (48) | velocimeter linvel 3, gyro 3, gravity `R_imu.T @ [0,0,−1]` 3, `qpos[7:] − default_pose` 12, `qvel[6:]` 12, delayed action 12, command 3 |
| Delayed action | `o[t+1]` carries `a[t−1]`; zero after reset |
| Control | `ctrl = default_pose + 0.5·a`, held 5 substeps, no clipping in Python; `xfrc_applied` cleared each Tick |
| Reset | `mj_resetData`, `qpos/qvel = default_qpos/qvel`, `ctrl = qpos[7:]`, `last_action = 0`, `mj_forward` |
| Perturbations | none: no observation noise, pushes, command resampling or auto-reset |

## Walking criteria (fixed before running) and measured values

Upright at every Tick means `up_z ≥ cos 45°`, trunk z ≥ 0.18 m, finite state and zero MuJoCo
warnings. `up_z` and trunk z come from the root free joint (`qpos[3:7]`, `qpos[2]`). Forward speed
is the trunk's Tick-to-Tick ground-plane displacement projected onto its current heading, averaged
over t = 2–10 s. A touchdown is a foot-floor contact flag changing false→true.

## Deviations from the design, and why

- **The policy JSON has no `joint_names` field.** Joint order is derived from `feet_geoms`
  (FR, FL, RR, RL) × (hip, thigh, calf), the Playground Go1 convention. `check_model` verifies that
  actuator *i* drives that joint through a joint transmission and that the joint sits at
  `qpos[7+i]` / `qvel[6+i]`.
- **Policy field names differ from the design's sketch.** The real file uses
  `policy.layers[i].{kernel, kernel_shape, bias, bias_shape, encoding}`,
  `normalizer.{mean,std}[obs_key]`, `observation_size[obs_key]` and `action_size`. The loader
  validates those names. It also fails closed on conventions the runner does not implement:
  non-null `normalizer.clip` or `control.clip`, a gait, a `task` other than `walk`, or a control
  target other than `default_pose`.
- **`--out` is the run directory**, and `run_id` is its name. An existing run is never replaced
  without `--overwrite`.
- **The zero-command displacement check uses the maximum horizontal displacement over the episode**
  (stricter than the final displacement; both are recorded).
- **Progress metrics stop at the last Tick before the first criterion violation**, so motion after
  a fall would not be credited. No violation occurred in these runs.
- The oracle copy is excluded from ruff so it stays byte-identical to upstream.

## Limitations

- **`walk.xml` collides feet only.** Trunk, thighs and calves have no floor collision, so non-foot
  ground contact cannot be observed in M0. A fallen body would pass through the floor. The upright
  verdict therefore rests on tilt, trunk height, finiteness and warnings only. M1 needs a collision
  approach for fall detection; examine weeble's `getup.xml` and its fall rule before choosing one.
- **The policy was trained in MJX (`impl: warp`) and is evaluated here in C MuJoCo.** Exact parity
  holds against weeble's C MuJoCo runner, not against the training simulator.
- **Identical results are claimed only within one build and machine.** Two runs here produced
  identical trajectories; other CPUs, BLAS builds or MuJoCo versions may differ numerically.
- **The policy JSON's license is inherited by assumption.** `policies/go1-walk-s0.json` has no
  separate license; `THIRD_PARTY_NOTICES.md` records the assumption that weeble's repository MIT
  license covers it.
- Only flat ground, nominal reset, constant commands and 10–51 s horizons were tested. M0 makes no
  robustness or sim-to-real claim.
